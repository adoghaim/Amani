### F042 — The free tier's 3-analysis limit can be bypassed by editing a claimed report's analytes or pointing a new report at a claimed file (latent until freemium is switched on)

- Location: `supabase/functions/generate-interpretation/index.ts:1832` · severity medium · category entitlement-bypass · owner_action=False

**Evidence**

A Free claim matches on blood_draw_id OR report_id (generate-interpretation/index.ts:1827-1834). The DB functions return 'already_claimed' on either: settle_introductory_claim (20261011000003_interpretation_version_ledger.sql:40) and commit_deep_access (20260925000001_commit_deep_access_rpc.sql:46). Nothing ties the claim to the data being interpreted. The prompt is built from report_analytes (index.ts:1363-1367), which the owner can INSERT, UPDATE and DELETE under RLS (20260312194342_add_canonical_analytes_and_report_analytes.sql:128-166; biomarkers likewise, 20260224062147:101-140). Route 1: after spending one credit on report R1, a user replaces R1's analytes with another draw via PostgREST and calls generate-interpretation with a new request_id. introductory-access.ts:209 returns existing_claim, deep generation runs, commit_deep_access_version settles 'already_claimed', and the full analysis is served and stored as Plus. The only limit is the 20/day rate limit (index.ts:1708). Route 2: a lab_reports INSERT only checks user_id (20260224062147:67-71); the column lock in 20260501000000 covers UPDATE only. So a new report can set file_url to the already-claimed file. The server hashes whatever file_url points to (index.ts:1889-1906), and the draw id collides with the existing claim. blood-draw-identity.ts:31-45 only considers users minting extra claims, not forcing a collision. This applies only once FREEMIUM_ACTIVE and the DB visibility switch are on (owner go-ahead pending). Verified by reading the code and migrations.

**Recommendation**

Fix before switching freemium on. Make report_analytes and biomarkers immutable for authenticated once a report has an interpretation (revoke UPDATE/DELETE, or add a trigger), or store a server-computed fingerprint of the analytes with the claim and refuse reuse when it changes. Make lab_reports.file_url server-owned, or require it to be a fresh object under '<user_id>/'. Add a regression test that edits a claimed report's analytes and expects Basic.

### F032 — lab_reports.file_url is client-writable on INSERT, and generate-interpretation downloads it with the service role without checking the owner's folder

- Location: `supabase/functions/generate-interpretation/index.ts:1896` · severity low · category authz · owner_action=False

**Evidence**

20260501000000_lock_lab_reports_user_write_columns.sql:22-26 narrows only UPDATE, so authenticated keeps INSERT on every lab_reports column, including file_url. In the throwaway DB, user A inserted their own report with file_url set to '<user B uid>/<ms>.pdf'. For Free-tier generation, generate-interpretation reads file_url and calls supabase.storage.from('lab-files').download(file_url) with the service-role client (index.ts:1891-1898), which bypasses storage RLS. It then stores the file's SHA-256 in content_hash, a column the caller can read (:1899-1904). delete-report already refuses foreign paths via resolveLabFileTarget (_shared/report-deletion.ts:125-160); this path has no such check. The impact is an existence oracle plus a hash of another user's file, and it requires knowing the victim's <uid>/<epoch-ms> path. The path is dormant while FREEMIUM_ACTIVE is off.

**Recommendation**

Before downloading, require resolveLabFileTarget(file_url, user.id).kind === 'owned'. Add a BEFORE INSERT check (or a column grant) so a client can only set file_url inside its own '<auth.uid()>/' prefix.

**Verifier's note**

Reproduced. In the fresh chain, authenticated user A inserted their own lab_reports row with file_url='<B uid>/<ms>.pdf' and it was accepted. Only UPDATE is column-restricted (20260501000000:22-26); the INSERT policy checks only auth.uid()=user_id, and the BEFORE INSERT triggers do not look at file_url. generate-interpretation uses a service-role client (index.ts:1660). It checks report ownership (:1735) but downloads file_url without resolveLabFileTarget (:1891-1898), then writes the SHA-256 into content_hash (:1899-1904). That is the only .download( call in functions or src. The impact is limited: an existence oracle and a hash, it needs the victim's UUID and the exact millisecond path, and it only runs in the freemium free-tier path.
