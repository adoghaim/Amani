### Detail per split / dependency

**EXP-1a (reminder delivery, revision 3)**
- **Channel.** Email through the EXP-1b provider first. Push comes later with native.
- **Email content.** Every reminder email is content-free: subject "You have a reminder in Amani", with the reminder type shown only in-app after login. This applies to all types, including period, fertile and ovulation, and keeps 1b's rule that email carries no cycle content (Decision R3).
- **Scheduler.** pg_cron and pg_net are absent from the harness image (postgres:15-alpine). Either schedule via a Supabase scheduled function outside migrations, or switch the harness image to supabase/postgres, and record which.
- **Timezone.** Store a timezone per user. `reminder_time` defaults to 08:00 with no timezone today.
- **Send ledger.** Idempotent, with a unique (user, reminder, period) key.
- **Existing `reminders` table.** It is user-writable. Decide whether it stays the store for user-defined reminders (the scheduler reads it read-only) or is retired.
- **Cycle prediction.** It runs only on the client (`src/utils/cyclePredictor.ts`). Extract a pure `_shared` predictor used by both the client and the scheduler, with parity tests.

**Every packet that adds a user-owned table (acceptance criteria, revision 3)**
- Erased by account deletion.
- Covered by the deletion-coverage test.
  - That test does not exist on main yet. Main's `delete-user-data.erasure.test.ts` checks a hand-kept list.
  - New packet **PK-DEL-SWEEP**, which must land before PK-EXP5 deploys: port PR #92's migration-derived sweep (`account-deletion-sweep.test.ts`) onto V2's erasure model. That model covers report-graph rows through `erase_reports` cascades, user tables through delete-user-data's ordered deletes, and the rest through the `auth.users` cascade. The sweep fails when a migration adds a user-owned table that none of these cover.
  - PK-03e-E is recorded as superseded by PR #93, except for this sweep test.
- Described in a Privacy.tsx entry marked for legal review.
- RLS cross-user denial proven in the harness.
- Reproductive-data tables (V2-04): the EXP-6 consent ledger is a hard dependency of their DEPLOY.

## Review decisions, sections 1-3 (2026-10-12)

**D5.1: AI kill switch when the config read fails**
- Edge functions use the last cached value (5-minute TTL).
- On a cold start with no cached value, AI stays ON. The existing per-user caps still apply.

**D5.2: AI budget**
- ALERT ONLY: alerts at 50%, 80% and 100%, with no automatic cutoff.
- The kill switch stays manual (R1 server key).
- Risk accepted: a bug or abuse spike can run up cost until someone acts. Alerts must reach a human quickly (see the alert-destination decision).

**D5.3: Pre-signup events**
- These go through a new edge function `log-anon-event`: IP-based rate limit (salted daily-rotating hash, never a raw IP), a global daily cap, and service-role insert.
- `log_app_event` is callable by authenticated users only.
- UTM, attribution and ref strings are restricted to `[A-Za-z0-9._-]` and at most 64 characters.
- Jarvis treats them as untrusted data.
- Applied to PK-EXP5 in the running factory (resumed with the revised spec).

**D5.4: Accuracy test set (EXP-7)**
- De-identified PDFs live in a private, access-controlled storage bucket, and CI downloads them with a secret.
- The repo holds only the expected-value JSON.
